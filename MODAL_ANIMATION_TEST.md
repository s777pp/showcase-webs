# Закрытый тест ИИ-оживления через Modal

Это **отдельный эксперимент**, пока без кнопки для посетителей. Публичный сайт,
его очередь, FFmpeg/gifski и существующий Modal-апскейл не меняются.
В GitHub/VPS ничего автоматически не отправляется.

## Нужно ли создавать новый API?

Нужен **новый сервис/URL**, но не новый аккаунт Modal. В том же workspace/environment
можно использовать существующие `MODAL_PROXY_TOKEN_ID` и `MODAL_PROXY_TOKEN_SECRET`:
[Modal Proxy Auth](https://modal.com/docs/guide/webhook-proxy-auth).
При ответе 401/403 проверь environment и права токена, а не заменяй рабочие ключи апскейла.
Доступ к CLI для `deploy` настраивается отдельно через `modal setup`.

Добавляется только `MODAL_ANIMATE_URL`. `MODAL_UPSCALE_URL` **не заменять**.
R2 используется тот же, с приватным бакетом: в Modal отправляются временные ссылки
на два файла, а не ключи доступа к хранилищу. Не публикуй .env, токены или подписанные URL.

## 1. Установка и развёртывание с компьютера

PowerShell:

```powershell
cd "C:\Users\n1t1337\Desktop\showcase-webs"
py -m venv .venv-animation
.\.venv-animation\Scripts\python.exe -m pip install -r requirements-animation-test.txt
```

Если Modal CLI на этом компьютере ещё не авторизован:

```powershell
.\.venv-animation\Scripts\python.exe -m modal setup
```

Разверни отдельный сервис, когда будешь готов использовать облачные ресурсы:

```powershell
.\.venv-animation\Scripts\python.exe -m modal deploy modal_animate.py
```

Первое развёртывание скачивает крупные веса модели в образ на стороне Modal;
сборка/загрузка могут занять время и используют облачные ресурсы. Я это не запускал.
В выводе будет HTTPS-адрес функции `api`. Скопируй его **без `/submit`** в локальный `.env`:

```dotenv
MODAL_ANIMATE_URL=https://YOUR-WORKSPACE--showcasemaker-animate-experiment-api.modal.run
```

В этом же `.env` должны быть существующие Modal proxy credentials и приватные R2
настройки, которые используются для апскейла. Если они пока только на VPS,
перенеси их в локальный .env самостоятельно через защищённое соединение — не в чат.
Тест также поддерживает `--env-file "полный\путь\.env"`. Переменные оболочки имеют
приоритет над файлом .env.

Проверка доступности **без запуска GPU** (не тестирует загрузку модели):

```powershell
.\.venv-animation\Scripts\python.exe scripts/test_modal_animation.py --health
```

После обновления ожидается `"protocol_version": 4` и пресет `alive`.
Версия 3 добавляет выбор движений и сборку по маске для закрытого эксперимента
в билдере. Настройка сайта описана отдельно в `BUILDER_AI_ANIMATION.md`.
Если версия старая, сначала повтори установку зависимостей и `modal deploy`
из этого раздела. Существующее окружение `.venv-animation` пересоздавать не нужно.
Обновлённый клиент отклоняет старый сервис до загрузки картинки.

## 2. Проверка картинки и первое оживление

Сначала локальная проверка: ничего не загружает, GPU не вызывает.

```powershell
.\.venv-animation\Scripts\python.exe scripts/test_modal_animation.py --image "C:\Users\n1t1337\Downloads\3131.jpg" --preset alive --intensity normal
```

Реальный запуск — **может списывать средства/кредиты Modal**:

```powershell
.\.venv-animation\Scripts\python.exe scripts/test_modal_animation.py --image "C:\Users\n1t1337\Downloads\3131.jpg" --preset alive --intensity normal --quality quality --output "animation-test-results\3131-alive-v2.mp4" --confirm-cost
```

`alive` — дыхание, моргание, небольшой наклон головы и движение плеч.
Другие пресеты: `breathing` (дыхание/моргание), `breeze` (ветер плюс оживление
персонажа, в том числе с короткими волосами), `water` (вода), `smoke` (дым).
`--intensity gentle|normal|strong` меняет описание амплитуды движения для ИИ,
а не гарантированный физический коэффициент. По умолчанию `alive`, `normal`, `draft`.
Режим `quality` в команде выше требует больше GPU-времени; для более дешёвого
первого теста явно замени его на `--quality draft`.
Свой запрос лучше писать по-английски:

```powershell
.\.venv-animation\Scripts\python.exe scripts/test_modal_animation.py --image "C:\path\scene.jpg" --preset custom --prompt "Very gentle moving clouds and shimmering lights. Preserve the entire scene." --confirm-cost
```

`draft`: 81 кадр, 30 шагов, около 3,4 секунды; `quality`: 121 кадр, 50 шагов,
около 5 секунд. Оба режима — 24 FPS. Для сравнения используй одну картинку и
один `--seed 42`; имена выходных файлов должны различаться.
Затем загрузи MP4 в наш билдер/обработку и оцени лицо, движение, стык цикла и качество GIF.

Во время ожидания показываются этапы загрузки, загрузки модели, шаги генерации,
проверка движения, кодирование и отправка. Возле MP4 сохраняется JSON с параметрами
и диагностикой, без подписанных ссылок. Существующие MP4/JSON не перезаписываются.
`WARNING: weak foreground motion` означает, что численная проверка обнаружила
слабое движение. Она исключает очевидный зелёный/синий фон и общий сдвиг яркости,
но не понимает изображение: мерцание или искажения могут пройти проверку, а очень
тонкое полезное движение — вызвать предупреждение. Автоматической повторной
платной генерации нет. Сохранившийся ролик можно оценить вручную.

Если соединение оборвалось, не запускай тот же тест с новым ID. Команда заранее
печатает ID задачи. Проверить/скачать результат **без новой генерации**:

```powershell
.\.venv-animation\Scripts\python.exe scripts/test_modal_animation.py --resume PASTE_REQUEST_ID --output "animation-test-results\resumed.mp4"
```

`--resume` не требует `--confirm-cost`: он только опрашивает уже созданную задачу.
Неизвестный исход отправки сохраняет резервирование — автоматического повторного
GPU-запуска нет. Если неизвестный статус не меняется, проверь Modal dashboard вручную.

## 3. Что получится и ограничения

Используется [Wan2.2 TI2V-5B](https://huggingface.co/Wan-AI/Wan2.2-TI2V-5B-Diffusers),
Apache-2.0, с закреплённой ревизией весов и Diffusers 0.36.0.
Это настоящий image-to-video с исходной картинкой, не имитация CSS-анимацией.
Первый пользовательский тест старой версии дал почти статичный ролик.
Обновлённые пресеты убирают ограничения «minimal motion»/«pose unchanged»;
качество **новой версии ещё не проверено реальным GPU-запуском**.

- Вход: статичные PNG/JPG/WebP до 8 МБ и 16 мегапикселей; GIF/видео пока не принимаются.
- Пропорции сохраняются вписыванием в кратный 32 холст, длинная сторона максимум 1280.
  Возможны небольшие поля. Это модельный размер, не размер итоговой нарезки Steam.
- Прозрачность превращается в фон `#061019`; можно изменить `--matte "#00ff00"`.
  ИИ может испортить однородность хромакея — сохранение альфа-канала не обещается.
- Движение, лицо и мелкие детали не гарантированы. Бесшовный цикл не гарантирован.
- Это не удаление фона и не массовая публичная генерация.
- Пять запусков в сутки UTC **на весь этот эксперимент**, включая неудачные/неопределённые
  отправки. Не лимитирует апскейл. Одновременно один L40S, с защитой от повторного
  исполнения одной задачи после входа в функцию;
  таймаут обработки одной задачи 20 минут. Очередь может заставить подождать.
- GPU масштабируется до нуля, но загрузка весов и короткий прогретый простой тоже
  могут стоить денег: [масштабирование Modal](https://modal.com/docs/guide/scale).
  Дневной лимит задач — не денежный потолок. Проверяй расходы в Modal dashboard.

Важно: [Modal может перезапускать упавший контейнер даже при `retries=0`](https://modal.com/docs/guide/retries).
Перед импортом GPU-библиотек и загрузкой модели записывается резервирование
исполнения. Повторный вход с тем же ID возвращает прежний результат либо ошибку
`execution_not_repeated`, не повторяя генерацию. Это **не** защищает от аварий
на этапе старта контейнера до входа в функцию, недоступности Dict или расходов
на сам перезапуск контейнера. При циклических сбоях останови только этот эксперимент
в dashboard. После неопределённого сбоя новую попытку запускай лишь осознанно,
с новым ID и подтверждением расходов.

Бесплатные кредиты Modal общие для аккаунта, включая апскейл. По текущему
[тарифу](https://modal.com/pricing) L40S стоит $0.000542/сек GPU, плюс CPU/RAM.
Это примерно $0.033 за минуту только GPU; длительность генерации надо замерить.
Не обещаем конкретное число бесплатных роликов до первого теста.

## 4. Хранение и остановка

При успешном скачивании удаляются только два приватных R2 объекта этой задачи.
Локальный MP4 остаётся у тебя. При сбое/прерывании объекты остаются, чтобы работал resume.
В Cloudflare R2 → **приватный бакет** → Settings → Object lifecycle rules добавь
удаление через 1 день **только для префикса `animation-experiment/`**.
Не применяй правило ко всему бакету или папкам апскейла/галереи.

Статус задачи доступен до 24 часов, без входных картинок и подписанных URL.
Технические записи/счётчики в Modal Dict не удаляются автоматически; для небольшого
закрытого эксперимента они остаются. После его окончания удаляй только выделенный
Dict `showcasemaker-animate-experiment-v1` через dashboard, когда нет активных задач.

Остановить сервис: Modal dashboard → Apps → `showcasemaker-animate-experiment` → Stop.
Это не останавливает приложение `showcasemaker-upscale`.

Остановить одну известную задачу (после обновления сервиса):

```powershell
.\.venv-animation\Scripts\python.exe scripts/test_modal_animation.py --cancel PASTE_REQUEST_ID
```

Это отменяет связанный вызов и завершает его GPU-контейнер; уже использованное
GPU-время не возвращается. При неопределённом ответе проверь dashboard.
Ctrl+C только прекращает ожидание на компьютере, **не** отменяет удалённую задачу.

## VPS и следующий этап

Для этого теста **обновлять VPS, Docker или nginx не требуется**. Всё запускается
с компьютера и обращается напрямую к закрытому Modal-сервису.
Сначала сравни 3–5 разных картинок. Если качество устроит, следующим отдельным этапом
подключим сайт: очередь, кнопку, пользовательские лимиты/согласие, приватность и
возврат результата в билдер. Сейчас эти публичные изменения намеренно не сделаны.
