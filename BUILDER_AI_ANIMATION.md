# ИИ-оживление кистью в билдере

Это закрытый эксперимент. По умолчанию выключен; доступ открывается только
авторизованным аккаунтам из списка email. Pro сам по себе доступ не даёт.
Обычная обработка и существующее оживление сцены работают отдельно.

## Настройка

1. Из папки проекта локально обнови **только приложение анимации**:

   ```powershell
   .\.venv-animation\Scripts\python.exe -m modal deploy modal_animate.py
   .\.venv-animation\Scripts\python.exe scripts/test_modal_animation.py --health
   ```

   Health должен вернуть `protocol_version: 5`. Эта проверка не запускает GPU.
   Если URL поменялся, обнови `MODAL_ANIMATE_URL` на VPS. Уже существующие
   `MODAL_PROXY_TOKEN_ID` / `MODAL_PROXY_TOKEN_SECRET` можно использовать снова.
   Не меняй URL апскейла. Новые ключи API для этого не нужны.

2. После загрузки кода на VPS добавь/измени в **действующем** `.env`:

   ```dotenv
   MODAL_ANIMATE_URL=https://YOUR-WORKSPACE--showcasemaker-animate-experiment-api.modal.run
   ANIMATION_ENABLED=1
   ANIMATION_ALLOWED_EMAILS=your-account@example.com
   ANIMATION_DAILY_USER_LIMIT=3
   ANIMATION_DAILY_GLOBAL_LIMIT=3
   ANIMATION_SEGMENT_DAILY_LIMIT=20
   ```

   Впиши email именно своего аккаунта сайта. Не публикуй `.env` в GitHub.
   Также необходимы уже настроенные приватный R2, Redis и внешний worker.

3. Из `/opt/showcasemaker` пересобери сайт и worker с обновлёнными переменными:

   ```bash
   sudo docker compose up -d --build --force-recreate app worker
   sudo docker compose restart nginx
   sudo docker compose logs --since=5m --tail=80 app worker
   ```

   Если переменные перечислены в `environment:` файла Compose поимённо,
   добавь туда эти четыре переменные **и в app, и в worker**, либо используй
   существующий `env_file`. Простого `restart` недостаточно для изменения env.

4. В приватном бакете R2 установи правило Lifecycle удаления объектов с префиксом
   `animation-experiment/` через 1 день. Только этот префикс, не весь бакет.
   Это временные исходники/MP4. После «Применить к слою» MP4 сохраняется как
   обычный приватный исходник билдера: правило эксперимента его не удалит.
   Для аварийно оставшихся входов распознавания добавь такое же отдельное правило
   на `animation-segmentation/`; при нормальной работе они удаляются сразу.

## Использование

Выбери в билдере слой с PNG, JPG или **статичным** WebP → «Оживить через ИИ».
Выбери тип изображения и движения: волосы, дыхание через ткань, глаза,
одежда, вода, дым или своё движение. Последняя выбранная категория — активная
кисть; можно разметить несколько категорий. Повторное нажатие на активную
категорию снимает её и удаляет её мазки. Кисть всегда рисует на исходнике,
независимо от поворота, позиции и масштаба слоя. Есть ластик и отмена мазка.

Для волос, одежды, ткани при дыхании и глаз доступна кнопка автоматического
выделения. Она запускает отдельный CPU-этап CLIPSeg и не вызывает Wan/GPU.
Каждая выбранная категория получает свою маску и процент уверенности. Проверь
подсветку: ИИ может пропустить тонкие пряди или неточно найти маленькие глаза.
Кисть добавляет область к найденной маске, ластик удаляет лишнее. Результат
кэшируется на сутки по содержимому изображения и набору категорий. По умолчанию
разрешено 20 новых распознаваний в сутки на аккаунт; значение задаётся через
`ANIMATION_SEGMENT_DAILY_LIMIT`.

Оставь фиксацию внешней области включённой и закрась нужные участки. Отключение
фиксации разрешает движение по всему изображению. Настрой силу и мягкость края;
дополнительное описание уточняет движение. Английский промпт можно посмотреть
до запуска. Подтверди использование **платного** GPU, затем запусти генерацию.

Для персонажей базовый промпт теперь имитирует сдержанную Live2D-анимацию:
голова, корпус, конечности, поза и силуэт фиксируются, а двигаться должны только
выбранные вторичные элементы. «Дыхание» меняет складки/светотень ткани, но не
поднимает грудь и плечи. Волосы выделяй без лица и корней, одежду — без тела,
глаза — только по векам. Широкая маска всё равно разрешит модели перерисовать
широкую область, поэтому лучше несколько аккуратных локальных мазков.

Сначала смотри MP4 в окне. «Применить» заменяет только тот исходный слой,
который ты оживлял, сохраняя его масштаб/поворот/позицию. Если слой уже изменён
или проект переключён, применение блокируется — видео всё ещё можно скачать.
Оригинальный файл не удаляется; замена входит в историю Undo билдера.

Идентификатор попытки создаётся в браузере и сохраняется **до** отправки файла.
Если ответ потерялся или страница перезагрузилась, сайт проверяет ту же задачу по
этому ID и не делает второй платный запуск. Последняя принадлежащая аккаунту
задача также находится на сервере, даже если журнал текущей вкладки потерян. В
этом случае результат можно посмотреть и скачать, но кнопка «Применить» скрыта:
без исходного контекста слоя безопасно заменить его нельзя. Закрытая завершённая
задача запоминается и не открывается снова автоматически.

## Важные ограничения и расходы

- Это Wan image-to-video, **не специализированная модель анимации по маске**.
  Категории и приблизительное расположение входят в промпт. Кисть фиксирует
  внешнюю область при последующей сборке кадров, а не гарантирует точное
  выполнение движений моделью. Внутри маски возможны искажения; на границах —
  стыки. Используй мягкие края и выделяй всю область движения с запасом.
- Автомаски создаёт CLIPSeg `CIDAS/clipseg-rd64-refined` (Apache-2.0) с
  закреплённой ревизией. Это текстовая семантическая сегментация, а не гарантия
  анатомической точности. Распознавание выполняется отдельно на CPU Modal.
- MP4 не имеет прозрачности. Прозрачный исходник кладётся на зелёную подложку;
  при применении включается хромакей. Для готового зелёного/синего фона настрой
  хромакей слоя. Зелёные элементы самого персонажа могут потребовать другого
  исходника. Бесшовная петля не гарантируется; используй зацикливание отдельно.
- GIF/видео не поддерживаются как источник этой экспериментальной I2V-функции.
  Не выбирается произвольная область уже готового видео.
- Черновик: 81 кадр / 30 шагов; качество: 121 кадр / 50 шагов, 24 FPS. Режим
  качества требует больше GPU-времени. Стоимость зависит от фактического времени
  Modal, в том числе загрузки модели; лимит попыток не является лимитом долларов.
- По умолчанию: 3 запуска на аккаунт и 3 на весь сайт в сутки UTC, плюс общий
  предел Modal эксперимента 5 попыток (включая CLI). Один активный запуск сайта.
  Ошибки/неопределённые результаты тоже расходуют попытку. Повторного платного
  запуска автоматически нет. Уведомление о слабом движении — только эвристика.
- Закрытие окна **не останавливает GPU**. «Остановить» передаёт запрос worker;
  остановка не мгновенная и не возвращает стоимость уже потраченного времени.
- При неопределённом ответе не жми генерацию снова: проверь запрос в Modal.
  Активный предохранитель держится до подтверждённого завершения либо до 125
  минут. После сбоя worker задача не перезапускается автоматически. Ручное
  возобновление CLI по ID только проверяет готовый результат, не платит повторно.
- Выключить кнопку: `ANIMATION_ENABLED=0` и пересоздать app. Уже запущенные
  генерации от этого не останавливаются: останови через Modal Dashboard.

Локальные тесты имитируют сервис и не запускают GPU. Проверка качества реальной
анимации остаётся ручной после настройки и явно подтверждённого платного запуска.
