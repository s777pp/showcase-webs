## 2026-10-01 (ночь) — 11 новых рамок

- 11 рамок по образцам владельца («Рамка 1» … «Рамка 11» в выборе формы): Обработка, «Ряды и квадраты» и
  «Создать дизайн». Работают все стили и анимации (переливы, зерно, неон, RGB и т. д.) и все типы витрин:
  Workshop (по частям или вся полоса), Featured, Artwork Split (506 + 100 — правая колонка зеркалит левую) и квадраты 150×150.
- Высокие рамки больше не сплющиваются на низких картинках: у дизайна может быть своя опорная высота (`refh`),
  тогда на низкой панели рамка целиком уменьшается, а украшения сверху и снизу сохраняют форму.
- В выборе формы рамки больше нет подписей под плитками: только картинки (название видно во всплывающей подсказке),
  у «Нет» вместо надписи значок.

### Как выложить

Только статика + Python: `bash deploy/update.sh` (пересборка app и worker, рамки рисует и сервер).

## 2026-10-01 (вечер) — исправления после выкладки

- Ошибки сайта больше не теряются при обновлении. Все ошибки сайта и обработчика (с трассировкой) и ответы 500
  сохраняются в базе: админка → «Ошибки сайта» (одинаковые собраны в одну строку со счётчиком, кнопки «Решено»,
  «Скопировать для разработчика», хранится 14 дней). Новая ошибка или вернувшаяся после «Решено» приходит в бота.
- Логи Docker ограничены: до 5 файлов по 20 МБ на сервис (раньше росли без ограничений).
- Импорт профиля: ссылка проверяется сразу. Если это не ссылка на профиль Steam, пользователь тут же видит, какую
  ссылку вставить (8 языков), задание в очередь не ставится. Раньше через минуту приходило «Не удалось открыть
  Steam-профиль», а в админке это считалось сбоем Steam.
- Уведомления о готовности и ошибках импорта профиля, оценки профиля, Steam DNA и удаления фона теперь приходят
  (раньше не доходили: у этих заданий другой формат владельца).
- `/api/steam/proxy-image` больше не отвечает 500, когда браузер параллельно запрашивает куски одного видео-фона
  (отдавался недописанный временный файл).

### Как выложить

`bash deploy/update.sh`. Таблица `server_errors` создаётся сама. Из-за новой настройки логов
`docker compose up -d` один раз пересоздаст все контейнеры, включая postgres и redis (данные на томах сохраняются,
сайт недоступен примерно 10–30 секунд) — лучше выкладывать в тихое время.

## 2026-09-30 (вечер) — цвета и скорость анимаций, безопасная выкладка

- Анимации текста: цвет эффекта теперь меняется и у огненной обводки (синий, зелёный и любой другой огонь).
  У каждого эффекта свой цвет по умолчанию; если выбрать свой — он сохраняется при переключении эффектов,
  кнопка «По умолчанию» возвращает родной цвет. Плитки показывают эффекты в их родных цветах.
- Скорость: ползунок ×0.25 … ×4, по умолчанию посередине (×1). Замедление и ускорение сохраняют бесшовный цикл.
- «Выпрыгивание» и «Расшифровка» больше не дёргаются на стыке цикла.
- Главная: облегчённая модель героя (`static/models/saba-0.1-web.vrm`, 12 МБ) теперь попадает в git
  (правило `models/` в `.gitignore` случайно скрывало её, поэтому сайт грузил запасную модель на 21 МБ).
- «Создать дизайн» — фон как на профиле Steam: фоны из каталога Steam теперь рисуются так же, как Steam рисует фон
  профиля, и витрина продолжает фон страницы без сдвига (Избранная и Иллюстрации совпадают до пикселя, Мастерская —
  с учётом зазоров между колонками). Геометрия снята с живого профиля и сверена со steam.design и steamprofile.io.
  Совмещение можно включить и для своего фона; ползунок «Витрина ниже на профиле» — если витрина не первая.
- Высота витрины меняется в реальном времени ручкой под холстом, кнопка «До конца фона» подгоняет её ровно под фон,
  пунктир показывает, где фон Steam кончается.
- Качество анимаций: дизайн больше не записывается с экрана. Каждый кадр рисуется в точное время (видео и GIF
  перематываются на нужный кадр), кодируется в VP9 с высоким битрейтом — ровно длина сцены, 30 кадров/с, без
  пропущенных кадров и без рывка на стыке петли (эффекты с частицами, видео и GIF плавно замыкаются).
  В браузерах без WebCodecs — прежняя запись, но ровно по длине сцены и с битрейтом 16 Мбит/с.
- «Скачать для Steam» прямо в «Создать дизайн»: дизайн сам уходит на нарезку (части Steam, GIF до 5 МБ, HEX 21),
  прогресс виден на месте, по готовности открывается окно с файлами и ZIP. «Дальше — нарезка» осталась для ручной
  настройки.
- Анимации «Дыхание» и «Волна» у персонажа теперь делают целое число циклов за сцену (петля без рывка);
  анимированные рамки берут время кадра, а не часы браузера.
- Выкладка: `deploy/update.sh` — одно обновление одной командой с проверками до сборки
  (владелец файлов, локальные правки, мешающие неотслеживаемые файлы, дамп БД, проверка готовности, smoke-тест).

## Как выложить (делает владелец)

### 1. В GitHub (`Desktop\showcase-webs`)
```powershell
cd C:\Users\n1t1337\Desktop\showcaseclaude
py -3.14 scripts/release_sync.py            # пробный прогон: список новых/изменённых файлов
py -3.14 scripts/release_sync.py --apply    # скопировать в showcase-webs (ничего не удаляет)

git add -A
git commit -m "Design studio: builder redesign, HUD frames, text animations, fast Steam backgrounds"
git push
```
`.env`, `data/`, `IMAGE/`, `output/`, `.claude/` не копируются. Переводы строк git нормализует сам (`.gitattributes`).

### 2. На VPS (`/opt/showcasemaker`)
```bash
cd /opt/showcasemaker
git rev-parse HEAD > ~/before-2026-09-30.txt                      # точка отката
docker compose exec -T postgres sh -c 'pg_dump -U "$POSTGRES_USER" -Fc "$POSTGRES_DB"' > ~/db-2026-09-30.dump
git pull --ff-only
docker compose config --quiet                                     # должно ничего не вывести
docker compose build --pull app worker                            # новые зависимости (pillow-heif) и Dockerfile
docker compose up -d
docker compose restart nginx                                      # nginx.conf смонтирован файлом: без рестарта останется старый
curl -fsS http://127.0.0.1:8080/api/ready && echo
docker compose exec -T app curl -fsS http://127.0.0.1:8080/api/health
docker compose logs --tail=80 app worker
python3 scripts/smoke_test.py https://showcasemaker.com
```
Ночной бэкап (`db-backup`) продолжает работать; ручной дамп — страховка именно на эту выкладку.

Необязательные строки в `.env` (без них работают значения по умолчанию):
`APP_MEM_LIMIT=3g`, `WORKER_MEM_LIMIT=6g`, `LOOP_PREVIEW_CONCURRENCY=1`.

### 3. Modal (отмена апскейла)
```powershell

```
Без этого апскейл работает как раньше; отмена останавливает только сторону VPS.
Если `modal deploy` падает с `TimeoutError` (сломанный IPv6 в сети: адреса `64:ff9b::…`), запускать через
`py scripts/modal_ipv4.py deploy modal_upscale.py` — то же самое, но только по IPv4.
