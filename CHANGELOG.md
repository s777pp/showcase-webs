## 2026-10-05 — новый хромакей, полосы и названия витрин в «Создать дизайн»

- Хромакей переписан (`smweb/chroma_matte.py` на сервере, `static/js/chroma-matte.js` в браузере, одинаковые
  формулы, тест сравнивает обе версии). Работает с фоном любого цвета (зелёный, синий, белый, чёрный, серый,
  розовый...), убирает только фон, связанный с краем кадра, поэтому белые блики/глаза на белом фоне и чёрная
  обводка на чёрном остаются; крупные «просветы» между руками убираются (для цветного фона любые).
  Края без каймы (цвет фона вычитается из полупрозрачных пикселей, зелёный отсвет снимается).
- GIF и видео больше не мерцают: цвет фона определяется один раз на ролик, прозрачность неподвижных
  пикселей сглаживается между кадрами (мерцание на неподвижных частях 1,49 % → 0,001 % на реальном ролике);
  кадр-заставка на другом цвете вырезается по своему фону. В «Персонаже» все кадры обрезаются одной рамкой:
  раньше персонаж менял размер, когда двигал рукой.
- «Персонаж»: выбор фона (авто, зелёный, синий, белый, чёрный, свой цвет), галочка «Убирать фон в
  просветах», предпросмотр сразу показывает вырезку (раньше показывал персонажа с фоном).
- «Создать дизайн»: те же новые варианты фона у слоя, чёрные полосы 3 px между частями витрины вместо
  пунктира, типы витрин по-русски: «Мастерская», «Избранная иллюстрация», «Витрина иллюстраций» (с подсказкой).

## 2026-10-03 (вечер) — YouTube по ссылке, Problembo

- Скачивание по ссылке (вкладка «Скачать» и «…или вставь ссылку» в Обработке): YouTube больше не отдаёт готовые
  файлы «видео + звук», поэтому старый выбор формата `best[height<=720]` падал («Requested format is not
  available») и пользователь видел «Не удалось скачать по ссылке». Теперь берутся лучшие видео + звук и
  склеиваются в MP4, в приоритете H.264/AAC (качество «до 720p» и «лучшее»).
- В образ добавлен Deno, yt-dlp ставится с решателем проверок YouTube (`yt-dlp[default]>=2026.8.19`): без
  JavaScript-движка YouTube отдаёт не все форматы. Новая минимальная версия заставляет Docker обновить yt-dlp.
- Problembo: при загрузке файла передаются `Content-Type` и `Content-Disposition` (ссылка подписана под них),
  ошибка создания задания больше не считается «битой картинкой» (теперь срабатывает следующий сервис), шаги
  и коды ошибок Problembo пишутся в лог без ключей.
- `scripts/check_bg_providers.py`: проверка каждого сервиса удаления фона одной тестовой картинкой.
- Problembo отвечал `PARSE_TASK`: публичный API называет поле с файлом иначе, чем форма на их сайте, а в документации
  оно не показано. Клиент перебирает форматы их других сервисов (`sourceImageFileIds`, `sourceImageFileId`, `images`…)
  и запоминает подошедший; закрепить можно `PROBLEMBO_BG_BODY=<имя>`. Код ошибки читается из `errorKey`.
  На VPS все 7 вариантов дали `PARSE_TASK`; добавлены варианты формы сайта (`uploadRoute` 0/1/2, `idempotencyKey`) и
  пробный режим `check_bg_providers.py --problembo-url` (их собственный формат со ссылкой на картинку).
  Поддержка Problembo: задания создаются через общий `POST /apis/v1/client/tasks` с типом в теле. По умолчанию теперь
  `{"protoType":"com.problembo.proto.PrBackgroundRemovalRequest","payload":{"images":[{"fileId"}]}}` (так задания
  хранит их сайт); `PROBLEMBO_BG_BODY=probe` перебирает остальные варианты.
  Итог: по описанию «AI background removal API» на странице сервиса тело — `{"sourceImages":[{"fileId"}]}` на
  `/background-removal/tasks`, результат — `GET /operations/{taskId}` (`SUCCEEDED`, `result.items[].url`). Догадки удалены.
- YouTube блокирует IP сервера («Sign in to confirm you’re not a bot», проверено на VPS 03.10). Поддержка cookies
  запасного аккаунта (`/data/yt-cookies.txt` или `YTDLP_COOKIES_FILE`) и прокси (`YTDLP_PROXY`); пользователь видит
  понятное сообщение на 8 языках, владельцу приходит уведомление в бота (не чаще раза в 6 часов). Инструкция: DEPLOY.md,
  раздел «YouTube downloads».

### Как выложить

`bash deploy/update.sh` (пересборка app и worker обязательна: новый Dockerfile и requirements).
Проверка: `docker compose exec app deno --version`, `docker compose exec worker python scripts/check_bg_providers.py`.

## 2026-10-03 — удаление фона: свой ИИ на Modal, выбор модели, запасные сервисы, чёрный/белый фон

- «Создать дизайн» → «Удалить фон через ИИ»: выбор модели — «Автоматически», «ИИ ShowcaseMaker» (наш BiRefNet на Modal,
  лучшее качество), iLoveAPI, Problembo, remove.bg. Показываются только настроенные сервисы.
- Пути отхода: если выбранный сервис не отвечает, занят или исчерпал месячный лимит, фон удаляет следующий
  (порядок `BG_REMOVE_ORDER`). Пользователь видит «X был недоступен, поэтому фон удалён через Y». Битая картинка
  в следующий сервис не отправляется.
- Подсказка для Modal: «Первое удаление после перерыва может занять до минуты…»; через 7 с ожидания статус
  «Запускаем ИИ-сервер…».
- iLoveAPI отдаёт PNG на 256 цветов — берём у него только прозрачность, цвета из оригинала (без ряби).
- Хромакей для GIF, видео и картинок: «Какой фон убрать» — автоматически / цветной / чёрный / белый. Чёрный и белый
  фон убираются по яркости с восстановлением цвета на мягких краях (свечение, дым, сглаживание).
- Лимиты: на пользователя как раньше (5/день Free, 20 Pro), на сайт 300 в день, у каждого сервиса свой месячный
  лимит (Modal 5000, iLoveAPI 240, Problembo 100, remove.bg 50).
- Админка → Состояние: «Удаление фона (ИИ)» показывает цепочку сервисов.
- Политика конфиденциальности (8 языков): Modal, а также iLoveAPI / Problembo / remove.bg.

### Как выложить

1. `py -m modal deploy modal_bg_remove.py`, адрес функции `api` → `MODAL_BG_REMOVE_URL` в `.env` на VPS.
2. В `.env` на VPS (по желанию): `ILOVEAPI_PUBLIC_KEY`, `PROBLEMBO_API_TOKEN`, `REMOVE_BG_API_KEY`.
3. `bash deploy/update.sh` (пересборка app и worker; статика с новыми `?v=`).
4. Проверка: админка → Состояние; в «Создать дизайн» удалить фон у картинки и хромакеем у GIF на чёрном фоне.
