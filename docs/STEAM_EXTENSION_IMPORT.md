# Надёжный импорт Steam-профиля через OpenID и расширение

> Реализовано в версии расширения **0.9.6**. Серверная часть находится в
> `main.py` и `auth_db.py`, сборщик Steam DOM — в `content-profile-import.js`,
> связь сайта с расширением — в `background.js`, кнопка запуска — на `/profile`.

## 1. Что должна делать каждая часть

Надёжный импорт нельзя строить на одном серверном запросе к HTML Steam. Система должна состоять из трёх источников:

1. **Steam Web API на сервере** — SteamID, ник, `avatarfull`, уровень, игры, недавние игры и список значков.
2. **Steam OpenID** — подтверждает, что пользователь действительно владеет конкретным SteamID.
3. **Расширение в браузере пользователя** — читает уже отрисованный профиль на `steamcommunity.com`: порядок витрин, Artwork/Split/Workshop, фон, видео фона, рамку, избранный значок, награды, группы и Custom Info.

OpenID не даёт доступ к оформлению. Расширение не должно получать или передавать пароль, cookie Steam или токены сессии Steam.

## 2. Нужные файлы расширения

Текущая папка исходников расширения:

```text
SteamShowcase-Helper-v0.9/
  manifest.json
  background.js
  content-profile-import.js
  popup.html
  popup.js
  icons/
```

Минимальная конфигурация Manifest V3:

```json
{
  "manifest_version": 3,
  "name": "SteamShowcase Helper",
  "version": "1.0.0",
  "permissions": ["storage", "tabs", "scripting"],
  "host_permissions": [
    "https://steamcommunity.com/*",
    "https://steamshowcase.up.railway.app/*"
  ],
  "background": { "service_worker": "background.js" },
  "content_scripts": [{
    "matches": [
      "https://steamcommunity.com/id/*",
      "https://steamcommunity.com/profiles/*"
    ],
    "js": ["content-steam.js"],
    "run_at": "document_idle"
  }],
  "externally_connectable": {
    "matches": ["https://steamshowcase.up.railway.app/*"]
  },
  "action": { "default_popup": "popup.html" }
}
```

При смене домена Railway оба адреса в `manifest.json` необходимо заменить и опубликовать новую версию расширения.

## 3. Безопасная схема импорта

### Шаг 1 — авторизация

Пользователь нажимает «Войти через Steam». Сайт запускает `/api/auth/steam/login`, Steam OpenID возвращает SteamID, сервер создаёт обычную сессию сайта и привязывает к ней SteamID.

На Railway обязательно настроить:

```text
APP_URL=https://steamshowcase.up.railway.app
STEAM_API_KEY=<ключ Steam Web API>
DATA_DIR=/data
```

К `/data` должен быть подключён Railway Volume. Без постоянного хранилища SQLite, снимки профилей и загруженные файлы будут пропадать после деплоя.

### Шаг 2 — одноразовый билет

Серверный маршрут:

```text
POST /api/profile/import-ticket
```

Он доступен только авторизованному пользователю и создаёт криптографически случайный билет со свойствами:

```json
{
  "ticket_hash": "sha256(...)",
  "user_id": 123,
  "steam_id": "7656119...",
  "expires_at": 1780000000,
  "used_at": null
}
```

Требования:

- время жизни 5 минут;
- билет используется один раз;
- в базе хранится только SHA-256 билета;
- билет привязан одновременно к `user_id` и `steam_id`;
- старые билеты пользователя аннулируются;
- ограничение: не чаще 3 импортов в минуту.

### Шаг 3 — запуск расширения

Сайт вызывает расширение через `chrome.runtime.sendMessage(EXTENSION_ID, ...)` и передаёт только одноразовый билет и URL собственного Steam-профиля:

```json
{
  "type": "IMPORT_STEAM_PROFILE",
  "ticket": "одноразовое значение",
  "profileUrl": "https://steamcommunity.com/profiles/7656119..."
}
```

Расширение открывает профиль или использует уже открытую вкладку. Оно обязано проверить, что SteamID страницы совпадает со SteamID, связанным с билетом. Импорт чужого профиля по билету владельца запрещается.

### Шаг 4 — ожидание полной страницы

`content-steam.js` должен:

1. дождаться `document.readyState === "complete"`;
2. дождаться `.profile_page` и `.profile_customization` через `MutationObserver`;
3. плавно прокрутить страницу до конца, чтобы Steam подгрузил lazy-media;
4. нажать локальные элементы «показать ещё», если они присутствуют;
5. дождаться, пока количество витрин и медиа не перестанет меняться минимум 800 мс;
6. только после этого собирать снимок.

Общий таймаут — 20 секунд. При таймауте отправляется частичный снимок с массивом `warnings`, а интерфейс предлагает повторить импорт.

## 4. Какие данные собирать

Расширение должно сформировать версионированный объект:

```json
{
  "schemaVersion": 1,
  "steamid": "7656119...",
  "profileUrl": "https://steamcommunity.com/profiles/...",
  "capturedAt": "2026-09-01T12:00:00Z",
  "profile": {
    "name": "User",
    "avatar": "https://...",
    "avatarFrame": { "animated": "https://...", "static": "https://..." },
    "background": { "poster": "https://...", "webm": "https://...", "mp4": "https://..." },
    "favoriteBadge": { "image": "https://...", "title": "...", "xp": "100 XP" },
    "badges": [],
    "awards": [],
    "groups": [],
    "showcases": []
  },
  "warnings": []
}
```

Каждая витрина хранится в исходном порядке:

```json
{
  "order": 0,
  "type": "workshop | artwork | featured | guide | info | gamecollector | items | unknown",
  "title": "Workshop Showcase",
  "images": [{ "url": "https://...", "width": 150, "height": 600 }],
  "links": [],
  "text": "",
  "stats": { "submissions": 50, "followers": 45 }
}
```

Для Artwork нельзя определять Split по числу картинок. Нужно сохранять фактическую ширину слотов: основной `506px`, боковой `100px`. Для Workshop сохраняются все пять колонок и фактическая высота каждого изображения.

## 5. Передача снимка на сервер

Серверный маршрут:

```text
POST /api/profile/extension-import
Authorization: ImportTicket <одноразовый билет>
Content-Type: application/json
```

Сервер выполняет проверки:

1. билет существует, не истёк и не использован;
2. SteamID JSON совпадает со SteamID билета;
3. профиль принадлежит пользователю билета;
4. размер JSON не превышает установленный лимит;
5. все URL имеют `https` и разрешённый Steam CDN-домен;
6. число витрин и медиа ограничено;
7. неизвестные HTML и скрипты удаляются;
8. билет атомарно помечается использованным;
9. снимок сохраняется только в запись этого `user_id`.

Ответ:

```json
{
  "ok": true,
  "snapshotVersion": 17,
  "imported": { "showcases": 8, "badges": 80, "groups": 1 },
  "warnings": []
}
```

## 6. Сохранение медиа

Нельзя полагаться только на внешние URL Steam: адрес может измениться, получить resize-суффикс или перестать открываться с Railway.

После принятия JSON сервер ставит задачу на зеркалирование медиа:

- аватар, рамка, значки и постеры — скачать в объектное хранилище;
- WebM/MP4 фона — сохранить в объектное хранилище с лимитом размера;
- Artwork и Workshop — сохранять оригинал без `imw/imh`, если он доступен;
- вычислять SHA-256, чтобы не хранить дубликаты;
- в снимке хранить `source_url` и `local_url`;
- при ошибке использовать `source_url`, а позже повторять загрузку.

Для Railway лучше использовать S3-совместимое хранилище (Cloudflare R2, Backblaze B2 или AWS S3). Railway Volume подходит для SQLite, но хуже подходит для большого количества GIF/видео и горизонтального масштабирования.

## 7. Аватар и данные API

После получения снимка расширения сервер повторно вызывает:

```text
ISteamUser/GetPlayerSummaries/v2
IPlayerService/GetSteamLevel/v1
IPlayerService/GetOwnedGames/v1
IPlayerService/GetBadges/v1
```

Правила приоритетов:

- аватар: `GetPlayerSummaries.avatarfull` → аватар из расширения → старый локальный аватар;
- уровень и игры: Steam Web API → старый снимок;
- рамка, фон и витрины: расширение → HTML-парсер → старый снимок;
- импорт никогда не должен заменять непустое старое поле пустым новым значением.

## 8. Проверка готовности

Перед публикацией провести минимум такие тесты:

- публичный профиль без рамки и фона;
- публичный профиль с анимированным фоном;
- профиль с Artwork 506+100;
- профиль с двумя Workshop Showcase;
- профиль с Featured Artwork и Guide;
- закрытый профиль владельца, открытый в его авторизованном браузере;
- два разных аккаунта в одном браузере — снимки не смешиваются;
- повторное использование билета возвращает 401/409;
- несовпадающий SteamID отклоняется;
- Steam CDN недоступен — показываются локальные копии;
- расширение отсутствует — сайт предлагает установить его и сохраняет серверный fallback.

## 8.1 Публикация обновления

1. Заархивировать **содержимое** `SteamShowcase-Helper-v0.9`, чтобы `manifest.json`
   лежал в корне ZIP.
2. Загрузить ZIP как обновление существующего расширения с ID
   `nopmeakgeongafdhgmlpllalpcfpedej` в Chrome Web Store Developer Dashboard.
3. Отправить версию `0.9.6` на проверку. Пока она не опубликована, магазин
   продолжит раздавать `0.9.3`, где связь с сайтом отсутствует.
4. Для проверки до модерации открыть `chrome://extensions`, включить режим
   разработчика, нажать «Загрузить распакованное расширение» и выбрать папку
   `SteamShowcase-Helper-v0.9`.

На Railway должны быть заданы `APP_URL`, `STEAM_API_KEY` и `DATA_DIR`, а к
`DATA_DIR` подключён постоянный Volume. Новые маршруты не требуют отдельного
секрета: одноразовые билеты генерируются сервером и хранятся в SQLite только в
виде SHA-256.

## 9. Что означает «почти 100%»

Гарантия возможна при выполнении условий: пользователь вошёл в нужный Steam-аккаунт, расширение установлено и имеет доступ к `steamcommunity.com`, страница профиля открывается в браузере и Steam не изменил DOM критически. Для обнаружения изменений DOM парсер должен возвращать подробные `warnings`, иметь `schemaVersion` и поддерживать удалённо обновляемый набор безопасных CSS-селекторов с серверной стороны. Код с сервера исполнять в расширении нельзя.
